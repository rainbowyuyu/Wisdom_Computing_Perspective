## 仍需处理的部署事项与边界

1. **高：历史凭据。** 前一轮记录表明 `.env` 曾被 Git 跟踪。本次确认当前忽略规则与部署包不会携带它，但删除现有文件不能使历史凭据失效。应在服务商/数据库/邮箱后台轮换曾暴露的凭据，并只更新服务器 `.env`；本次没有代为轮换，也不把凭据写进报告。
2. **高：服务器资源与运行身份。** 之前只读排查发现服务器约 1.6 GB 内存，多个服务共用资源，网站处于 `bt.service` 的 cgroup。应将网站迁至独立的非 root 服务/容器，再为该服务设置总内存和 CPU 限额。**不能直接限制或停止整个 bt.service 来限制网站**，否则可能同时影响宝塔面板。应用级上限不能代替系统隔离或网络层防护。
3. **高（条件性）：自定义 Python。** 现有执行权限仍仅授予主管理员和显式可信账号；AST 检查与资源限制不是完整安全沙箱。不要把 `WISDOM_CODE_RUNNERS` 开放给普通用户。开放不可信执行前，必须隔离文件、密钥、系统调用与网络。
4. **中：内容与存储。** 生成视频仍是持有随机链接即可读取，不是按账户鉴权的私密视频库。长期运行还需要总存储配额、过期视频清理和磁盘告警；当前头像替换清理并不等同于全站存储配额。本次没有删除历史用户资料或视频。
5. **中：完整 CSP 与第三方资源。** 本次 CSP 限制 object/base/frame/form；尚未启用严格的 script-src nonce，因为现有页面有大量内联交互。动态加载的图谱/编辑器及其子资源尚未全部实施 SRI。后续应逐步本地化关键依赖、移除内联执行，并重跑当前未完成的 CDN 漏洞审计。
6. **中：代理配置。** 生产反向代理必须覆盖而非转发客户端伪造的 `X-Real-IP`、`X-Forwarded-Proto`、`X-Forwarded-Host`；应用端口不应直接暴露公网。网站目前使用单进程内存会话与连接计数，多 worker 不能直接靠增加参数启用；横向扩容需要共享会话和限流存储。

## 部署本次修改

1. 先备份网站文件、数据库及服务器自己的 `.env`，保留正在运行版本的依赖记录。
2. 压缩包中的 `html_root/` **内容**对应网站根目录，例如 `/www/wwwroot/wiscomper.com/`。覆盖相同相对路径，不再多套一层 `html_root`。
3. 在宝塔中停止**网站自己的 Python 项目**，使用该项目的 Python 环境执行 `python -m pip install -r requirements.txt`，再执行 `python -m pip check`。不要对宝塔面板的 Python 环境执行升级。不要仅覆盖代码而遗漏依赖更新。
4. `.env.example` 仅作参考，不覆盖现有 `.env`。新增可配置入口并发上限 `API_HTTP_MAX_CONCURRENT=16`、单 IP 同时请求上限 `API_HTTP_MAX_PER_IP=8`。保留原有用户日额度、模型预算、渲染并发及代理配置；拥挤校园/公司网络可结合资源监控调整单 IP 上限。
5. 本次没有新增 MySQL 表，不需额外运行 SQL。内部 SQLite 重试记录仍由应用自行维护。
6. 仍以 `python main.py` 启动。先验证健康接口、登录、换绑邮箱、保存算式和一个简单动画，再放开正常流量。重启会使内存中的旧登录会话失效，需要重新登录。

若依赖安装或小流量验证失败，恢复备份版本及其依赖，保留数据库与 `.env`。不要通过取消权限/资源校验来绕过部署问题。
