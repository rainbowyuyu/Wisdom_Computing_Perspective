# 单题识别与运行稳定性更新 · 2026-09-20

## 使用变化

- 每次上传或输入一道完整题目；本题的小问、选项和方程组可以一起保留。移除多道题同时提交的引导，同一账户最多保留一道正在处理的后台题目。不同账户仍可并发，同题内依赖明确的小问仍可并行。
- 图片识别与智能体图片入口使用统一规则，保留完整题干、公式和明确的图形标注。识别完成先核对，再进入计算，不自动拿不确定内容开始求解。
- 空白、损坏、过大图片在模型调用前拦截。无法识别时保留原图，单独显示提示，支持裁剪、重试或手动补充；错误不再填进公式编辑器。
- 模糊内容要求确认。核心公式修改会同步替换题面中匹配的表达式；无法匹配时提示核对完整题面，计算以完整题面为准。
- 等待识别时显示进度提示并可取消。重复点击不重复请求，切换图片、手动编辑或取消后，旧请求结果不能覆盖新内容。
- 修复新版手写画板笔迹显示和透明图片导出；识别时输出黑字白底。智能体识别结果转入核对页时也带入原图。

## 运行保护

沿用现有并发限制、模型预算、超时和子进程隔离，增加主机可用内存与磁盘空间检查：

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| HOST_MIN_AVAILABLE_MEMORY_MB | 256 | 低于此值暂停新重任务；已排队后台任务等待资源恢复 |
| HOST_MIN_FREE_DISK_MB | 512 | 网站或临时目录所在磁盘空闲不足时暂停新重任务 |
| HOST_EMERGENCY_AVAILABLE_MEMORY_MB | 96 | 运行中的数学/渲染子进程在巡检时停止，释放本站计算资源 |

所有配置从现有 `.env` 读取，不需要覆盖服务器配置。Windows 读取系统内存；Linux 同时参考主机可用内存与可读的 cgroup v2 上限。资源不足在新请求扣额度前拒绝，返回明确提示，不自动循环请求模型修复。浏览、结果读取和取消入口不受这项重任务检查影响。后台资源等待不会重复收费。

这些措施降低资源耗尽风险，不能保证整机永远不会崩溃。巡检存在间隔，应用外的其他服务不在本程序控制范围内。生产服务器仍应使用独立的网站服务/容器设定总资源上限；不要限制或停止整个 `bt.service`，以免影响宝塔面板。不会删除用户历史数据或旧视频。

## 部署

部署包包含本轮修改及尚未发布的上一轮安全加固，保持 `html_root/` 相对目录；它是现有 v0.4.7.2 网站的覆盖更新包，不是完整新站安装包。

1. 先备份网站和数据库。将包内 `html_root/` 的内容覆盖到现有网站根目录，不额外套一层目录。
2. 保留服务器自己的 `.env`、运行数据与视频。包中不包含凭据文件、运行数据库、日志或用户上传文件。
3. 按 `SECURITY-AUDIT-20260920.md`，在网站自己的 Python 环境安装 `requirements.txt` 并运行 `python -m pip check`。不要升级宝塔面板本身的 Python 环境。
4. 继续通过 `python main.py` 启动或重启网站项目；无新增 MySQL 表，无需额外执行 SQL。重启后内存会话可能需要重新登录。
5. 检查 `/healthz`、登录、一道清晰题目的识别核对、一个简单分步解答和动画。资源保护参数先用默认值，再根据服务器监控调整。
