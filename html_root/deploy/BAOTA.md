# 宝塔部署与已有数据库升级

## 1. 上传目录

将 `html_root` 上传到例如 `/www/wwwroot/wiscomper_com/html_root`。下文路径可替换为你的实际目录。网站不需要上传仓库上级的训练项目、桌面程序、论文或其他目录。

正式网页由 Python 服务提供。不要把整个 `html_root` 当作可公开下载的静态目录；Nginx 通过反向代理访问网页，只由 Python 暴露 `static` 内的资源。

## 2. 在数据库面板执行 SQL

在宝塔「数据库」中先备份 `wiscomper_com`，进入 phpMyAdmin 后：

1. 左侧选中 `wiscomper_com`，确认顶部显示「数据库：wiscomper_com」。
2. 点击「SQL」，复制 `html_root/visdom_db.sql` 全文并执行；长文件也可通过「导入」上传同一文件。
3. 执行过程应无报错，末尾结果显示 `upgrade_status = OK`、`current_database = wiscomper_com`、`total_tables = 30`（自行添加过其他表则更多）、`applied_migrations = 6`。`missing_columns`、`missing_indexes`、`missing_relations`、`migration_conflicts` 和 `pending_legacy_wrongbook` 均应为 `0`。

**数据库更新只需执行这一个 SQL 文件，无需依次执行 `database/migrations` 内的文件，也无需运行 Python 生成脚本。** 它既能初始化空库，也能升级原网站 18 张表及后续 29 张表版本，包含用户权限、额度、管理员审计和请求题目记录等目前全部 30 张表。

脚本补齐旧弹幕表的颜色与显示模式字段、索引和关联，将能精确匹配用户名的旧错题复制进新错题本；原表和内容保留。重复执行不会重复导入旧错题，也不会重置密码、VIP/管理员角色、停用状态、自定义额度、已用次数或联系方式，不会自动给任何账户提升权限。`unmatched_legacy_wrongbook` 表示仍保留在旧表、未匹配到账户的旧错题数，可以大于 `0`。

升级结尾检查字段、索引和外键是否齐全，核对已有迁移校验和，成功后登记当前迁移版本。随后启动 `python main.py` 时会验证相同的记录，不再重复执行这些迁移。若显示 `NEEDS_ATTENTION`，按非零的缺项和前面的 SQL 报错检查；`migration_conflicts` 非零时核对部署代码与历史版本，脚本不会覆盖已有校验和掩盖冲突。此校验检查必需结构是否存在，不会擅自改写自行修改的字段类型或修复未知版本结构。

无需修改 SQL 里的库名，也无需 `CREATE DATABASE` 权限。数据库账号需要当前库的建表、改表、索引和读写权限。无需存储过程或临时表权限。单文件脚本兼容 **MySQL 5.7 / 8.0**；正式部署仍建议使用受支持的 MySQL 版本。MariaDB 未完成整套验证。

若此前在 `FROM JSON_TABLE(...)` 处遇到 `#1064`，表示当前数据库不支持这项语法。新版脚本已将全部结构检查和版本登记改为普通 `SELECT / UNION ALL`。选中原数据库，重新执行新版 `visdom_db.sql` **全文**即可接续完成；不用删除之前创建的表或清空迁移记录，已有业务数据保留。最后仍以无报错且 `upgrade_status = OK` 为完成标准。

更新时先暂停网站进程，避免两个导入或应用启动迁移同时修改结构，完成后仍用 `python main.py` 启动。如果提示「没有选择数据库」，重新选中左侧数据库后执行。如果新增外键提示旧数据没有对应父记录，先核对记录归属并修复再重试；脚本不会为通过检查而删除数据或关闭外键检查。MySQL 改表会逐条提交，执行前的数据库备份是回退依据，报错后可以修正问题再重新执行整个文件。

维护者新增迁移时，先更新 `visdom_db.sql` 中的建表定义与升级规则，再运行 `python scripts/build_database_installer.py` 同步自检清单及迁移校验和；`--check` 可验证生成结果没有过期。已执行过的迁移文件不可直接修改。

## 3. 安装 Python 与动画环境

在宝塔 Python 项目管理中创建 Python 3.11 或 3.12 虚拟环境，并将工作目录设置为 `html_root`。Ubuntu / Debian 的系统依赖示例：

```sh
sudo apt-get update
sudo apt-get install -y build-essential python3-dev pkg-config libcairo2-dev libpango1.0-dev ffmpeg texlive-xetex texlive-latex-extra texlive-fonts-recommended texlive-lang-chinese dvisvgm fonts-noto-cjk
python -m pip install -r requirements.txt
```

其他 Linux 发行版使用对应的软件包管理器。这里的 `python` 应使用宝塔项目虚拟环境内的解释器。LaTeX、dvisvgm 和中文字体用于公式与中文动画，FFmpeg 用于视频输出。

安装或更新 TeX 后，用运行网站的同一账号、同一 Python 环境执行：

```sh
python scripts/check_manim_tex.py
```

自检会实际编译普通公式、中文「且」、分段函数、矩阵、向量范数和组合数。显示 `ready` 才表示这条 Manim 排版链路已通过；只运行 `latex --version` 不能确认中文与 SVG 转换可用。纯数学公式使用 LaTeX，含中文的公式自动使用 XeLaTeX、ctex 与 Fandol 字体，再交由 dvisvgm 转成矢量图。所需宏包包括 amsmath、amssymb、mathtools、bm、mathrsfs、cancel 和 ctex。

Windows 上可继续使用现有 MiKTeX，在 MiKTeX Console 中补齐这些宏包及 Fandol 字体，先完成一次自检，避免首次渲染时临时下载宏包或生成字体缓存。若提示某一步语法或命令错误，应修正该步公式；编译器、宏包或字体缺失则按具体提示补齐环境。

## 4. 配置并启动

复制 `.env.example` 为 `.env.local`，填入当前库的连接信息：

```dotenv
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DB=wiscomper_com
MYSQL_USER=宝塔数据库用户名
MYSQL_PASSWORD=宝塔数据库密码
ALIYUN_KEY=自己的模型服务密钥
VIDEO_TOKEN_SECRET=自行生成的长随机字符串
```

环境变量优先于 `.env.local`，`.env.local` 优先于 `.env`。不给模型服务密钥时，AI 识别和生成无法调用远程服务。

宝塔启动命令设置为虚拟环境中的 **`python main.py`**；监听地址默认 `127.0.0.1:8000`。可通过环境变量 `HOST` 和 `PORT` 修改。`main.py` 会统一启动正式网页、全部 API、流式解答、播放器 WebSocket 与数据库迁移检查；无需单独启动其他 Python 文件或 Vue。旧的 `python start.py` 仍调用同一个启动函数。进程用户需要能写入 `static/avatars`、`static/videos`、教学视频存储目录和系统临时目录。

使用一个进程，**不要开启 reload 或多个 worker**：现有登录会话、渲染任务和播放器 WebSocket 房间保存在进程内。重启会要求用户重新登录；服务器重启后让宝塔自动拉起此进程。

### AI 额度与安全配置

游客累计可试用 3 次计算、2 次识图、2 次智能体、2 次创作助手和 3 次动画。按浏览器标识与 IP 哈希双重计数，刷新或清除 Cookie 不会单独重置，同一公共 IP 的游客共享试用额度；全部网络身份同时变化仍不能彻底识别为同一自然人。试用结束提示登录。典型例题和教学案例阅读不计额度；后台持久任务和个人存储需要登录。

普通用户默认每天 40 次功能提交（计算、识图、助手、动画共享），北京时间每日 00:00 恢复。仅主账号 `rainbow_yu` 可设置默认日额度、个人日额度、重置当天用量、授予或取消管理员 / VIP、停用用户。后台整题新提交或手动继续计 1 次，子任务与自动动画不重复扣个人次数；同一活动题和同一请求标识重复提交不重复扣次。普通同步解题与动画各为一次提交，开始执行后失败或取消不退次数。VIP 和管理员免个人日次数额度，仍遵守全站成本上限、并发、速率及自定义代码权限。

模型请求全站默认每日最多 300 次，游客 IP 每日最多 80 次；每账户每分钟 6 次、同时最多 2 次，全站默认同时 4 次。资源或分钟速率繁忙时最多等待 60 秒，排队不调用模型。每次上游请求（包括规划、子题、纠错和失败）都计入全站模型成本，全站模型计数仍按 UTC 零点恢复。设 `AI_ENABLED=0` 可暂停远程模型调用。旧的 `AI_REQUIRE_LOGIN`、`AI_USER_DAILY_CALLS`、`AI_GUEST_DAILY_CALLS` 已由这套数据库权限替代，不再作为个人权益配置。

`AI_DAILY_TOKEN_RESERVE` 默认 2,000,000，使用文本 UTF-8 字节数、图片保守预留及输出上限累计预留，不是供应商实际账单或精确 token 统计。每次输出默认最多 7000 tokens；SDK 自动重试关闭。仍应在供应商控制台设置消费告警和预算。个人次数免限不等于关闭全站成本保护。

额度记录在 `html_root/var/usage.sqlite3`，网站进程需可读写该目录。**部署时保留 `var/`，不要将其加入 Git 或暴露为静态目录**。计数使用 SQLite 原子事务；数据库异常时停止模型调用。系统不在额度文件记录原题或密钥。相同账户的同题与相同上下文可复用十分钟内完成的解答；缓存最多 64 条，只在内存中保存，不跨账户共享。保存算式默认本地生成知识标签；`AI_FORMULA_TAGGING=1` 才启用收费模型辅助打标。

自定义 Python 执行（开发者渲染、关键帧及旧 `/api/animate/stream`）默认关闭。只有主账号 `rainbow_yu` 且数据库角色为管理员时可执行自定义 Python；也可在 `WISDOM_CODE_RUNNERS` 中配置可信操作者的**完整用户名**，多个名字以逗号分隔。此权限等同于运行服务端 Python；现有语法检查不能充当安全沙箱，不应授予普通注册用户。普通学生仍可使用 `/api/solve/render` 的固定、数据驱动 Manim 场景，代码助手也可生成和下载建议代码。

Nginx 必须覆盖 `X-Real-IP`、`X-Forwarded-Host` 和 `X-Forwarded-Proto`，不要透传客户端提供的这些请求头。默认仅信任 `127.0.0.1,::1` 的直接代理，其他代理需配置 `TRUSTED_PROXY_IPS`；Uvicorn 不再自动信任任意转发链。公网只暴露 Nginx，Python 保持监听回环地址。`Host` 与 `X-Forwarded-Host` 使用 `$http_host` 保留浏览器地址中的端口。

### 登录提示「请求来源不受支持」

本站正式地址是 `https://www.wiscomper.com`，当前服务器网站目录是 `/www/wwwroot/wiscomper.com`（直接对应本地 `html_root` 内容）。部分旧宝塔代理将 `Host` 改成 `127.0.0.1:8000`，会使原来的来源校验误拦截 HTTPS 登录。

修复需要一起上传 `app/request_origin.py`、`app/request_guard.py`、`app/routers/auth.py` 到网站目录的相同相对位置，然后在宝塔 Python 项目管理中重启原 `main.py` 项目。无需改动数据库，也不要覆盖服务器的 `.env`、`.env.local` 或 `var/`。

未配置或留空 `ALLOWED_ORIGINS` 时，默认明确允许 `https://www.wiscomper.com`；本地 `http://127.0.0.1:8000`、`http://localhost:8000` 等同源地址和原 Vue 开发入口仍可使用。其他域名默认按代理保留的外部协议、域名和端口校验；确需跨域部署时，在服务器 `.env.local` 设置精确的 `ALLOWED_ORIGINS`，例如 `ALLOWED_ORIGINS=https://www.wiscomper.com,https://wiscomper.com`，重启生效，不要使用 `*`。显式配置会替换默认正式域名白名单，必要时包含 www 地址。

宝塔网站的现有反向代理规则建议按 `deploy/nginx.conf.example` 保留外部域名和协议；不要整体替换宝塔的站点配置或证书。HTTPS 代理继续设置 `proxy_set_header X-Forwarded-Proto $scheme;`，以便正确标记登录 Cookie。源码修改及配置保存后必须重启 Python 进程；仅刷新网页不能更新后端校验。

`.env` 和 `.env.local` 只留在服务器，不上传 Git。旧 `.env` 曾被版本库跟踪，应在供应商控制台更换旧密钥，并检查历史提交中其他凭据；删除当前版本文件不会撤销历史凭据。

### 用户类型与管理员初始化

新增 `account_access`、`access_settings`、`access_usage`、`access_audit` 四张 MySQL 表，已纳入 `visdom_db.sql` 和 `005_account_access.sql`。用户角色绑定数值用户 ID，管理后台另外严格校验主账号 `rainbow_yu`，不接受浏览器传入的角色；注册默认普通用户。主页显示账户类型、剩余额度和联系作者申请 VIP 入口，主账号可从主页「用户管理」或右上角「管理」打开管理中心。停用在下一次 API 或模型调用前生效，已发送到供应商的请求可能已计费。

部署到其他服务器后，在服务器终端执行 `python scripts/grant_admin.py --username rainbow_yu` 并交互输入该账户密码。若账户尚不存在，可加 `--create` 创建后授予权限。脚本先校验现有密码，不覆盖已有密码；不得把密码写入命令参数、前端代码、SQL 或版本库。当前本机已完成主账号验证与授权。主管理员不能在网页管理页降权或停用，账号名不能从资料页修改，密码仍可按原功能修改。

如果只能使用宝塔数据库面板，数据库管理员可选中网站实际使用的库，执行 `deploy/grant_owner.sql` 全文。它仅将精确匹配的现有 `rainbow_yu` 设置为管理员并解除停用，不修改密码、个人日额度和使用记录，同时写入授权审计。结果 `owner_status = OWNER_ENABLED` 表示成功；`ACCOUNT_NOT_FOUND` 表示选错库或该库尚无此账号，不会创建或授权近似拼写的账号。成功后刷新网页（必要时退出重登）即可出现管理入口，无需重启服务。这个授权脚本独立于通用数据库升级脚本，普通升级不会自动提升账号权限。

普通用户、VIP 及其他管理员身份均不能调用管理 API；其他管理员身份不会获得任意 Python 执行权限。默认作者邮箱沿用 `rainbowyu619@gmail.com`，管理员可在管理中心修改。角色、停用状态和额度调整写入审计记录；不会向管理页返回密码散列。保留业务 MySQL 备份及 `var/` 运行记录。

### 后台拆解任务与并发

长题、多小问，以及普通推导只完成部分的题目，会转到智能体后台任务。缺少图形或必要条件时先提示补充，不无限重试。也可在智能体勾选「拆解题目 · 后台任务」主动提交。每题最多 6 个子目标，独立目标并行，依赖结果完整完成后才继续；部分结果不会作为已证结论传给后续任务。

每账户最多 3 道活动题，全站最多 24 道；调度器最多 4 个解题工作、每账户最多 2 个。动画单独排队，后台每账户最多 1 个，固定场景与开发者渲染共用 2 个渲染位置。模型客户端仍执行统一账户/IP/日额度限制。超出容量显示排队或拒绝提示，用户可以停止单题或只重试未完成部分。

`html_root/var/math-tasks.sqlite3` 自动创建，无需修改业务 MySQL 表。该文件存储原题、补充条件、依赖计划、题解与动画地址，API 按登录账户隔离读取，响应禁止缓存。任务在页面切换、刷新后继续；进程重启时标记「待恢复」，已完成结果保留，用户点击继续才重新调用模型。启动时清理超过 7 天的任务；新提交时仅保留全站最近 100 条结束任务。需要长期保存的题解请通过阅读窗口存入「我的算式」，动画媒体应随原有用户媒体目录一同备份。

继续使用 `python main.py` 单进程运行，并保留可写的 `var/` 目录。当前调度适合有界并发，不能通过增加 Uvicorn worker 横向扩容；多实例部署需另行引入共享队列和会话存储。

### 模型故障与重复提交保护

模型额度与故障保护状态存放在 `var/usage.sqlite3`，请保留可写权限和持久目录。日调用次数和 token 预留上限继续由 `.env` 中的 `AI_GLOBAL_DAILY_CALLS`、`AI_DAILY_TOKEN_RESERVE` 控制；VIP/管理员也受全站模型预算保护。需要紧急暂停付费调用时设置 `AI_ENABLED=0` 并重启，本地计算仍可用。

同一用户正在处理的相同解题、智能体和动画 JSON 请求返回 409，等待当前结果即可；参数校验失败返回 422，这两种情况不再扣功能次数。模型 401/403 会暂停相同配置的后续调用 5 分钟，429 暂停 1 分钟，短时间内连续连接/超时/服务端故障暂停 30 秒，避免故障期间重复消费。修正密钥并重启后使用新的配置；日志和保护数据库不记录密钥原文。

动画统一有界排队，超过 60 秒会提示稍后重试。矩阵视频每轮最多渲染 180 秒、关键帧 90 秒、其他视频 240 秒；取消时清理 Manim 及 TeX/FFmpeg 子进程后才归还名额。

分步动画遇到可修复的 LaTeX 错误时，会先释放渲染名额，请模型判断并仅修复出错步骤的公式排版，再重新排队生成；不执行模型返回的 Python。开发者视频和完整关键帧预览允许模型修复脚本，通过现有语法/导入限制检查后再渲染，执行权限仍限管理员。按行断点预览不自动改脚本，以免原断点错位。每次请求最多一次模型诊断与修复；旧版双阶段动画的预览、视频和两个阶段共用这一次机会。缺少编译器、宏包、字体、权限、资源或排队超时不会触发模型修复。修复失败或额度不足时保留题解并提示，不再循环重试。

模型修复仍受全站 token 预留、日调用预算、频率、并发和故障熔断约束。成功后将修复公式或代码回传页面，供用户继续保存、复用；代码编辑期间的新改动不会被覆盖。分步动画页面等待上限调整为 13 分钟，包含两轮渲染和一次修复，期间持续发送进度/心跳，可随时停止。请求与重复提交占位最多保留 30 分钟，正常完成或取消立即释放。故障恢复后不会自动重放已失败的请求。

## 5. 连接域名

将 [nginx.conf.example](nginx.conf.example) 的 location 配置合并到宝塔站点现有 `server` 块，保留域名、证书和验证文件配置，替换原有同名 `location /`，不要重复添加。移除覆盖这些路径的旧反向代理或静态缓存规则。

配置支持流式解答、WebSocket 和较长动画请求。测试配置通过后重载 Nginx。首次部署依次验证：网页打开、账户登录、保存算式、创建课包、打开错题本、生成一次短动画。

## 6. 后续更新

替换网站源码时保留服务器配置与用户媒体目录，再执行最新版 `visdom_db.sql` 或让应用按 `database/migrations` 检查升级。不要修改已经执行过的历史迁移文件。Vue 源码在 `frontend/`，当前正式静态网页无需前端构建步骤。

### 邮箱验证与找回密码

此版本要求所有账号先验证邮箱，主账号、VIP 和普通账号一致。旧账户仍能用原用户名和密码登录，登录后填写常用邮箱并验证；账号权限、额度和学习资料不变。没有绑定邮箱又忘记密码的旧账户，需要联系作者核实身份，不能仅凭填写一个新邮箱找回账号。

上线前先在服务器 `html_root/.env` 配置以下项目，本地使用自己的 `.env`。若已有 `.env.local`，同名项目会覆盖 `.env`，请避免保留过期的发信配置：

```dotenv
SMTP_HOST=你的邮箱服务商提供的SMTP地址
SMTP_PORT=465
SMTP_USERNAME=发件账户
SMTP_PASSWORD=邮箱服务商的SMTP授权码
SMTP_FROM=已获准的发件邮箱
SMTP_FROM_NAME=智算视界
SMTP_USE_TLS=1
EMAIL_CODE_SECRET=替换为独立的至少32字符随机密钥
EMAIL_CODE_EXPIRE_SECONDS=600
EMAIL_SEND_COOLDOWN_SECONDS=60
EMAIL_DAILY_LIMIT=10
```

465 端口使用隐式 TLS；587 端口配合 `SMTP_USE_TLS=1` 使用 STARTTLS。授权码通常不是邮箱登录密码。确认服务器可访问所选端口，发件地址已通过服务商验证，并根据服务商说明设置 SPF/DKIM。不要将这些配置提交到 GitHub，也不要写入前端文件。密钥可以在服务器用 `python -c "import secrets; print(secrets.token_urlsafe(48))"` 生成并保存；更换密钥会使尚未使用的验证码失效。

启动 `python main.py` 会执行新增的 007、008 迁移；也可直接在宝塔数据库面板执行最新版 `visdom_db.sql`，它同时包含旧库字段补齐和新表创建，无需逐个导入迁移文件。原有用户的邮箱默认未验证，不会自动绕过验证。务必在启用新版本前配好邮件服务，未配置时页面会明确提示暂不可用，不会返回测试验证码或放行注册。

验收时用自己的测试邮箱完成：新注册、旧账号登录后绑定、退出重进、忘记密码、验证码过期或错误后重试。重置密码会退出该账户全部已有登录会话。当前项目会话与图片验证码仍采用单应用进程存储，部署保持一个应用 worker；邮件验证码和发送限制由数据库保存，重启后仍有效。

#### wiscomper.cn 腾讯企业邮箱配置

`wiscomper.cn` 使用腾讯企业邮箱时，将服务器 `html_root/.env` 中的邮件配置设为：

```dotenv
SMTP_HOST=smtp.exmail.qq.com
SMTP_PORT=465
SMTP_USE_TLS=1
SMTP_USERNAME=noreply@wiscomper.cn
SMTP_FROM=noreply@wiscomper.cn
SMTP_PASSWORD=该邮箱的客户端专用密码或授权码
SMTP_FROM_NAME=智算视界
```

`SMTP_USERNAME` 和 `SMTP_FROM` 填同一个真实存在的完整邮箱，不能只填域名，也不能填两个 `@`。登录企业邮箱网页版，在设置中查找「客户端设置」「收发信设置」或「客户端专用密码」，按该账户页面的提示开启 SMTP 并生成专用密码；入口名称可能因企业邮箱版本不同而变化。没有相关选项时，需企业邮箱管理员检查第三方客户端使用权限。不要把网页登录密码直接当作授权码。

客户端授权码只填入本机或服务器的 `SMTP_PASSWORD`，不必发到聊天中。保存后重启 `main.py`。本机配置不会自动同步到宝塔；服务器也需要在其自己的 `.env` 中填写配置。邮箱改名后，请同步修改 `SMTP_USERNAME` 与 `SMTP_FROM`，并确认授权码属于该邮箱。生产环境保留其独立的 `EMAIL_CODE_SECRET`，不要覆盖数据库、模型或其他已有配置。

验证码默认 10 分钟有效，错误 5 次后失效；同邮箱至少间隔 60 秒、每日默认 10 次，同来源每日 30 次、同已登录账号每日 10 次，全站每日 500 次。找回密码对未绑定邮箱与已绑定邮箱返回相同提示。验证码仅保存服务端摘要，不写入请求记录，过期两天的验证码记录在启动时清理。未配置 SMTP 的测试可通过注入邮件发送器进行，生产环境没有绕过验证的开关。

### 启动报 Unknown collation: utf8mb4_0900_ai_ci

这表示数据库不支持 MySQL 8 的排序规则，与报错堆栈中的 Python 3.10 无关。更新网站的 `app/database.py` 后，用 `python main.py` 重新启动。迁移会检查服务器能力：支持时保留原规则，不支持时使用 `utf8mb4_general_ci`。不需要删库、清空迁移记录或修改历史 SQL 文件；之前失败的迁移会重新执行，已存在的表和原始记录保留。

此修复针对排序规则兼容问题，不代表所有旧版 MySQL / MariaDB 功能都已完成验证。完整部署仍建议使用 MySQL 8.0+。


### 请求记录

`006_request_records.sql` 新增 `request_records`，单文件 `visdom_db.sql` 已同步为 30 张表。启动 `main.py` 自动迁移，已有数据不清空。索引覆盖时间、用户、类型、状态及后台任务 ID。题目、账号快照、时间、状态、耗时、浏览器/系统类别仅主账号可查；题面最多 12,000 字，图片原文、代码和请求凭据不记录。后台队列最多 512 项，满队列或写入异常不阻塞解题，管理页提示记录可能不完整。后台拆题的实际状态会同步，HTTP 202 不代表完成。

查询最多读取最近 90 天，默认 7 天、每页 20 条。每小时触发一次最多 500 条过期数据的清理（仅有新记录写入时触发），备份的清理需沿用服务器备份策略；日志开始前的历史输入不追溯采集。重启后超过两小时仍处于活动状态且未恢复的请求标为中断。管理入口、查询和详情 API 都逐次校验主账号身份；其他管理员不能查看、授予权限或读取请求内容。
