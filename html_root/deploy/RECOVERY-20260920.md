# 服务器无响应后的恢复与修复

适用于本次计算隔离修复包，基于 v0.4.7.2。无需修改数据库，仍用原虚拟环境的 `python main.py` 启动。

## 先恢复登录

若网站、宝塔、SSH 同时无响应，先在云服务商控制台查看实例状态、CPU、内存和磁盘监控，尝试 VNC / 救援终端。能进入时先保存故障时段日志，再停止宝塔中智算视界对应的 Python 项目。若系统仍完全无响应，再从云控制台重启实例；不要重装系统或删除数据库。

如果网站和 SSH 已恢复，不要为了应用修复重复重启整台机器。先停网站项目，备份代码及数据库，再部署。只有端口可连接不能证明网站或宝塔登录正常，应分别检查。

恢复后可执行以下只读命令检查资源和 OOM 记录；最后两条可能需要管理员权限。重启前的日志仅在系统保留历史日志时可用。

```sh
uptime
free -h
df -h
ps -eo pid,ppid,comm,%cpu,%mem,rss --sort=-rss | head -25
journalctl -k -b --no-pager -n 300
journalctl -k -b -1 --no-pager -n 300
```

重点检查 `Out of memory`、`Killed process`、磁盘写满与异常进程数量。不要使用 `killall python`，避免误停宝塔和其他服务。诊断输出留在服务器，不要公开包含用户内容的应用日志。

## 覆盖修复文件

1. 在宝塔停止**智算视界**的 Python 项目。确认没有第二个项目管理器重复启动同一服务。
2. 备份压缩包清单中对应的原文件；保留服务器 `.env`、`.env.local`、`var/`、数据库、上传文件和教学视频。
3. 压缩包内 `html_root/` 的**内容**覆盖到 `/www/wwwroot/wiscomper.com/`。例如 `html_root/main.py` 对应 `/www/wwwroot/wiscomper.com/main.py`，不要多嵌套一层 `html_root`。
4. 单独的早期计算隔离修复无需新增依赖；当前累计包已包含安全依赖升级，必须使用网站自己的 Python 环境执行 `python -m pip install -r requirements.txt` 和 `python -m pip check`。无需执行 SQL。`.env.example` 只是配置说明，不要用它覆盖已有密钥配置。累计部署以 `DEPLOY-ALL-SINCE-LAST-PUSH-20260920.md` 为准。
5. 在宝塔启动原项目：虚拟环境的 `python main.py`，单进程，不启用 reload 或多个 worker。

默认已启用以下保守设置，无需添加环境变量也生效。如需显式配置，将这些项写入服务器现有 `.env.local` 并重启项目。系统环境变量优先，其次 `.env.local`、`.env`。

```dotenv
MATH_MAX_WORKERS=1
MATH_WORKER_MEMORY_MB=384
MANIM_MAX_CONCURRENT=1
MANIM_WORKER_MEMORY_MB=768
```

计算使用独立进程，超时或取消后终止并回收；计算容量占满时明确提示稍后再试。动画一次运行一个任务，其他动画继续沿用有期限的排队。资源上限失败不会触发模型纠错或自动重试。正常的公式、语法错误仍保留有限次数的自动修复。

Linux 对计算及动画子进程设置地址空间和 CPU 时间限制，动画进程降低优先级并限制数值库线程数。地址空间上限包括库映射，不等同于实际物理内存；TeX、FFmpeg 子进程各自继承限制，**不是所有进程总和的内存上限**。Windows 启用进程隔离、超时回收和并发限制，不使用 Linux 的资源限制接口。

生产服务器还应为整个 Python 项目配置 cgroup / systemd 的总内存、CPU 和进程数限制，为宝塔、数据库、Nginx 和系统预留资源。根据服务器实际内存及正常动画峰值设置，不能只依赖上述单进程限制。不要另外启动一个 systemd 服务与宝塔抢占同一项目；若更换托管方式，先停原进程并取消原自动启动。

## 上线检查

```sh
curl --max-time 5 http://127.0.0.1:8000/healthz
curl --max-time 10 https://www.wiscomper.com/api/solve/capabilities
```

`/healthz` 应返回 JSON `{"status":"ok"}`，不是 HTML 首页。它仅确认 Web 服务能响应，不代表数据库、邮箱或模型服务全部正常。若旧版本把未知路径返回为首页，即使状态码为 200 也不算本次修复已上线。

登录后用 `x^2-5*x+6=0` 验证分步计算和动画，取消一次任务，再提交一道题确认可以继续使用。观察服务器内存、CPU、子进程数量是否在任务结束后回落。部署前不要在正在故障的服务器上运行压力测试。

本地已检查独立计算、取消回收、异常退出、资源不足停止重试，以及真实 Manim 视频生成。Linux 的资源限制仍需在实际服务器上验证。没有故障时段的服务器日志，不能仅凭网页超时认定 OOM 或认定问题已彻底消失。
