# 账号与模型权限检查 · 2026-10-23

本轮覆盖邮箱登录、旧库兼容、GitHub 会话共存、模型权限和账号界面；不是对外部模型、邮件投递或 GitHub 可用性的保证。

已修复的风险：

| 级别 | 问题 | 处理 |
|---|---|---|
| 高 | 普通在线用户可直接提交收费模型选项 | `server/model_access.py` 与 `/api/jobs` 在预留额度前检查可信角色；只默认开放 Qwen。 |
| 高 | 反向代理来自 loopback，容易误获本机权限 | 公网配置一律关闭本机例外；本机模式还检查实际 peer、URL 和转发头。 |
| 高 | 旧账号角色撤销或改密后仍沿用登录时快照 | 每个 API 请求读取权威用户与角色；每设备冻结密码版本，旧设备失效不会影响已用新密码登录的设备。 |
| 高 | 按用户名或相同邮箱自动合并 GitHub/旧账号 | 使用数据源命名空间和可信数字用户 ID；不做名称自动关联。 |
| 中 | 验证码重放、跨用途使用或无限试错 | 验证码按邮箱、用途和用户绑定，保存 HMAC，单次使用，错误次数与发送量持久限制。 |
| 中 | 登录覆盖访客工程或跨用户读取 | 复用事务迁移、轮换会话/CSRF和记录所有权检查；旧库原始内容保留。 |

密码使用兼容旧站的 bcrypt；公有会话不包含密码哈希、密码版本、SMTP配置或模型凭据。邮箱操作保留来源与 CSRF 校验，错误信息不回显输入和上游异常。SQL 值采用参数绑定；旧资料作为受限文本导入，脚本不执行。`.env`、数据库、临时目录和凭据保持在静态路由之外。

验证用临时数据库、模拟邮件与模拟模型；真实旧库仅做只读连通和表结构检查。真实 GitHub 授权仍待运营者完成 Client Secret 配置，未把模拟测试称为实际授权成功。

依赖检查：`npm audit --omit=dev` 报告 14 个受影响包条目（5 高、8 中、1 低，包含传递影响，不等于 14 个独立漏洞）。涉及 DSH 携带的 MCP/Office 组件、AJV 的 `$data` 模式及 KaTeX 的既有原型污染条件。当前场景工具没有注册 MCP/Office，AJV 不启用 `$data`，但这不代表依赖本身已修复。本轮未自动跨预发布版本升级 DSH，也未把审计结果写成零风险；后续应单独升级并复核运行时、公式渲染和导出。依赖提示分别见 GHSA-6qxp-vccf-f47h、GHSA-6prh-2h8m-c8cw、GHSA-px8p-9vwx-vf98、GHSA-2g4f-4pwh-qvx6、GHSA-238p-pmpm-9mq7。
